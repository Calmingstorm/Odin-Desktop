# Odin Desktop: source reuse map

Updated after settled D1-D6 decisions, 2026-10-04. The file inventory remains a static proposal against the recorded baseline, not implementation approval.

## Scope and evidence

The inspected baseline is Odin `cd7530906e9cfa10a0fa900247d7ce2a8bb33e25` (v4.13.0). References below are baseline-relative paths and one-based line numbers. Only source was inspected; no imports, tests, builds, dependency installation, endpoint probes, configuration changes or service operations were performed. A verdict describes the proposed desktop destination, not whether the present code already works there.

- **keep as is**: copy the source byte-identically at its Odin path and track it in the Desktop port ledger. Relocation alone is not an adaptation. Any wording-only change, including D1's approved Discord substitutions, is an explicit ledgered exception; it must not be silently treated as substantive equivalence.
- **keep with adaptation**: copy the source and make only specified Desktop changes, each explicitly tracked in the port ledger.
- **strip**: remove the feature's registrations, configuration, dependencies, documentation and UI references from Desktop. There is no remote-client mode in the first versions.
- **replace**: provide the named Desktop equivalent, with the replacement and its divergence tracked in the port ledger.

### Settled product boundaries

- **D1 prompt:** the Desktop prompt changes only the Discord references, using the exact wording Aaron approves in `prompt-changes.md`; all other prompt content stays unchanged. Such wording-only changes to a keep-as-is source are explicit tracked exceptions, not silent substantive edits.
- **D3 lifecycle:** the core is a supervised child of the Desktop app. Closing the window hides the app and the core continues; Exit stops it. There is no independent daemon or window-lifetime mode. Without a tray, relaunch focuses the app and Exit remains available in the window menu and launcher actions.
- **D4 maintenance:** code is copied and maintained in this repository. There is no shared core package and no Odin-repository extraction. [maintenance.md](maintenance.md) defines baseline selection, test closure, the bidirectional port ledger and safety drift gates.
- **D5/D6:** no existing-user data import path and no remote-client/phone access in the first versions. Keep the protocol seam only. This does not remove SSH remote managed-host tooling: controlling configured remote infrastructure is distinct from accessing this Desktop instance remotely.
- **History read:** the Desktop tool is `read_conversation`, adapting `read_channel` to the authenticated current conversation transcript. It accepts no caller-selected foreign conversation ID.

All tracked files in `src/`, including package initializers and runtime assets, and every tracked `ui/js/pages` module are accounted for below. User access control can go; execution authority, secret protection, target consent, output authorization, completion classification and response guards cannot.

### Tool extraction constraints

- **Remove human RBAC, not execution authority.** Discord membership/tier administration, shared-human ACLs and local bearer-grant management may disappear. Exact action/target approval, host enrollment/trust/leases, governor restrictions, secrets, native consent, trusted-code admission and retained-output authorization remain. Do not label every desktop request admin to bypass current restrictions.
- **Keep remote infrastructure.** SSH, host enrollment, host-vantage probes, remote commands/scripts, remote jobs and qualified Linux patch targets remain essential. Local OS portability is separate from target OS capability. A Windows desktop controlling a Linux server still needs SSH and remote Linux tooling.
- **One coherent engine lifetime.** Executor/deps share live locks/stores/services (`src/tools/executor.py:248-294,309-355`), process registry (`:618-637`) and output authority (`:639-751`). Identity/timeouts are task-local even with one human (`:91-115`): concurrent conversations, schedules and agents still race. Module globals for catalogues, URL grants/timezone and process owners need explicit profile/process ownership, not accidental UI-thread sharing. UI hiding, engine exit, sleep and crash recovery are distinct states; resume does not replay uncertain effects.
- **Qualify the platform, do not weaken guarantees.** `/proc`, pidfd/subreapers, POSIX groups/signals/shells, OpenSSH utilities, private modes, `/tmp`, service/log commands, renameat2 and fsync are load-bearing assumptions. Retain qualified Linux backends; future native backends preserve ownership/transaction semantics or return unsupported. Windows ACLs are not implemented by `chmod`; macOS lacks Linux pidfd/renameat2 guarantees.
- **Separate authorization and presentation.** A cursor is not authority; full text/binary retrieval must check live origin/tool/host generation before loading. Text scrubbing, binary access and streaming are different boundaries. Safe renderer/download IPC cannot expose raw credentials or auto-execute artifacts. UI attachment failure is not tool failure, and stream completion is not effect settlement.
- **Reuse hazards are explicit, not tested away.** Workspace is cwd protection, not a sandbox; in-process skills are trusted code. Post-dispatch SSH retries and MCP teardown diagnostics need review; browser launch currently disables sandbox; branch diagnostics fetch and ignore their timeout. Automatic operational validation must actually execute later, not rely on an appended hint. Conditional schema descriptions still require downstream concrete-payload validation (`src/tools/defs/media_scheduling.py:82-226,241-344`; `src/tools/defs/tasks_knowledge.py:12-61`). No behavior, dependencies, shutdown, provider endpoints or cross-platform claims were exercised here.

## Cross-cutting copy-and-maintain risks

### 1. Transport-neutral orchestration is not just removing Discord imports

`src/discord/tool_loop.py:1109-1181` derives request metadata, channel/thread context, bot/webhook provenance and scoped tools from message/channel objects and channel policy. `src/discord/wiring.py:99-153,156-190,1175-1355` constructs services but tears them down through a bot root. `src/web/chat.py:62-169,278-332` demonstrates a working duck-typed adapter, not a clean core protocol. Copy the engine into Desktop under Odin paths and adapt its request envelope, conversation service, control service and typed delivery sink, maintaining both repositories under D4. Preserve tool-loop policies, classifiers, guard ordering and result semantics. Apply only D1's exact Aaron-approved Discord wording substitutions to prompt text; keep all other prompt content unchanged and ledger wording-only deviations explicitly.

The prompt/preset source names Discord (`src/llm/system_prompt.py:16-34,66-114,116-134`). D1 resolves that conflict: replace only Discord references using the exact wording Aaron approves in `prompt-changes.md`; leave all other text unchanged. Record those wording-only changes as explicit tracked exceptions, not silent substantive adaptations. Do not append desktop-specific always-on guidance. Runtime metadata and tool descriptions are separate from the prompt change.

### 2. Durable user transcript is a missing product boundary

Model sessions are budgeted, summarized and archived (`src/sessions/manager.py:1095-1116,1797-1826`). Web chat reload reconstructs messages but drops files/tool cards (`ui/js/pages/chat.js:433-461`); fake-channel files only exist in the turn response (`src/web/chat.py:73-76,111-126,328-332`). Add a distinct durable message/artifact/event store, with stable IDs, retention, export and deletion semantics. Preserve session compaction for model context; never use it to truncate the user-visible record. Tool evidence's bounded retention/cursors are not permanent chat attachments.

### 3. Background delivery and scheduling assume a live gateway destination

Schedules bind destination/requester at creation (`src/discord/native_tools/scheduling.py:112-126`), resolve a numeric Discord channel when firing (`src/discord/scheduled_events.py:503-509`) and use gateway-connection epochs for admission (`src/scheduler/scheduler.py:374-418`; `src/__main__.py:650-655`). Loops retain channel objects and `asyncio` tasks (`src/tools/autonomous_loop.py:125-167`); skill callbacks send immediately or stage per channel (`src/discord/native_tools/skills_tools.py:199-218`). Replace destination lookup and connection admission with core-owned conversation/inbox readiness. A hidden window must not lose output or block valid schedules; Exit stops the supervised core. Preserve admission-generation fencing and non-retryable uncertain effects; changing the sink does not make replay safe. Runtime state and durable history are not automatic agent/loop/workflow crash resumption.

### 4. Single-process globals and one-writer assumptions

The web adapter explicitly assumes one bot per process and owns module-scope channel locks (`src/web/chat.py:23-29,196-224`). Channel state uses event-loop-owned maps/inboxes (`src/discord/channel_state.py:82-115,133-218`); restart intent is process-global (`src/restart.py:24-41`). A desktop profile needs exactly one owner of mutable stores/scheduler/worker lifecycle, explicit private IPC discovery and profile-generation locking. The UI is a client, not another process importing managers against the same data directory. Multiple windows/profiles are not permission to share mutable singletons or live SQLite/JSON files between installations.

### 5. Linux/POSIX native execution is not portable merely because Python is

The strict patch engine requires Linux `renameat2(RENAME_NOREPLACE)` with no unsafe fallback (`src/tools/apply_patch.py:963-990`). Local process supervision inspects `/proc`, uses `prctl` subreapers and pidfds (`src/tools/local_supervisor_worker.py:35-88`); startup wires POSIX event-loop signal handlers (`src/__main__.py:696-701`). Computer containment and input backends add systemd/bubblewrap/X11/D-Bus/portal/Hyprland dependencies, documented above. Retain a Linux implementation behind platform capability boundaries. Windows/macOS need independently designed and qualified identity, descendant cleanup, transactional filesystem and input-release implementations. Porting only command syntax is not safety parity. Unavailable native support means no tool publication, not weaker fallback.

### 6. Desktop authority is local-owner authority, not no authority

Strip multi-user tiers, guild access, role/user administration and standalone API-token inventory. Preserve secret redaction, untrusted-source provenance, command governor, host identity/trust and target leases, execution workspace fences, retained-output access checks, effect uncertainty and explicit supervised computer consent. Existing config path protection includes credentials, audit, sessions and native storage (`src/config/workspace_paths.py:1-34`); it must protect new desktop profile roots too. No remote-client/phone access in first versions. SSH remote managed-host operations remain subject to the remote host's identity/tool/host policy. A hostile attachment, renderer script or another local process does not become the owner because it shares a machine.

### 7. Paths, privilege, secrets and coexistence

Config defaults contain working-directory-relative data paths and a root SSH user (`src/config/schema.py:42-59,77-91`); runtime installation root follows the Python package (`src/runtime_paths.py:8-10`). Replace deployment-relative state with independently namespaced per-user config/data/cache/log/runtime roots and immutable packaged resources. Separate credentials, known-hosts, model caches, browser state, workspaces, audit/retained evidence, computer resources and profile locks from an existing Odin server. No automatic shared-live-data mode and, under D5, no existing-user data import path. Never default the desktop core or renderer to root merely because Aaron's server install runs that way.

### 8. Startup, packaging and updates must change together

Current restart re-execs the Python application after drain and refuses reexec when cleanup cannot be proven (`src/restart.py:1-11,49-59,80-85`); web update applies an install-tree update then requests restart (`src/web/api/self_update.py:83,264-267`). Replace the git/deployment updater with a packaged UI/core update contract and safe worker settlement. D3 is fixed: the app supervises the core, window close hides and continues, Exit stops Odin; there is no daemon or window-lifetime mode. Per-user login autostart is optional packaging integration, not boot-before-login operation. Startup/update must not mutate or restart an alongside Odin installation.

### 9. Management UI reuse is workflow reuse, not today's chat in a shell

Provider setup, configuration, hosts/trust, tools/skills/MCP, knowledge/memory, schedules, agent/loop/process state and observability are reusable workflows. Their server endpoints/admin gates and transport schema still need adaptation. Rebuild chat around attachments, conversations, durable output, in-turn stop/steer, evidence and background inbox. Remove obsolete pages, routes, config fields, registrations, descriptions, documentation and dependencies consistently. A hidden Discord-config tab with active backend references does not satisfy the brief's stripping rule.

### 10. Design uncertainty and next-round boundaries

This map is a static baseline inventory. It does not claim binary/package/platform acceptance, full dependency closure, endpoint parity or empirical startup/cleanup correctness. Module-specific keep verdicts are scoped to their current contracts, not portability guarantees for all transitive imports. Native shell choice and distribution formats remain design details; D3-D6 settle lifecycle, copy-and-maintain (no shared package or Odin extraction), no existing-user data import, and no first-version remote-client/phone access. The protocol seam remains, and SSH remote managed-host tools remain distinct. No runtime validation was performed here.
